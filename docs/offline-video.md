# 本地视频逐帧分析

实现：`src/video/mp4.ts`、timeline、job、protocol、offline.worker，以及 PoseStage。

格式检查和 MP4Box 容器索引在 Worker 中运行。WebCodecs 按解码顺序处理，结果按源显示时间审计。MediaPipe 在 Worker 中运行离线和摄像头推理，离线预览和推理共用同一张位图。视频和图像帧保留在浏览器内。

导入层 `src/video/prepare.ts` 不以扩展名拒绝文件，单视频和双视频对比共用。MP4Box 与 WebCodecs 能直接读取的文件保持原数据；其他容器、编码、碎片化 MP4 或轨道变换先由浏览器本地单线程 FFmpeg WebAssembly 转为 H.264/yuv420p 普通 MP4。资源从本站 `/ffmpeg/` 读取，通过 `pnpm prepare:assets` 从锁定依赖复制并校验，纯静态部署也可使用，不要求跨源隔离或 CDN。

常见容器包括 MP4/MOV/MKV/AVI/WebM/FLV/WMV/MPEG/TS/3GP/OGV/MXF 等，实际解码能力以随附 FFmpeg 核心为准。损坏、加密、无视频轨道或仍无法解码的文件会显示错误。输入最大 500 MB。FFmpeg 从挂载的本地文件分段读取，转换输出仍占用 WASM 内存。转换最多运行 10 分钟，可主动取消。换源、替换文件或卸载组件会终止转换 Worker 并释放内存。

转换选取第一条视频轨道，应用旋转和像素比例，输出最长 1920×1080 的偶数尺寸并去掉音频和字幕。passthrough 帧同步保留可变帧率间隔。转换后再次验证 MP4 索引和 WebCodecs 支持。完整性核对和时间轴以转换后视频为准。会话、工具证据与 CSV 的 `acquisition_mode` 使用 `webcodecs-transcoded` 标记转换路径。

源呈现帧超过 18,000 时，按呈现顺序均匀抽取帧进行姿态推理，覆盖首尾。解码仍核对完整呈现序列，结果最多保留 18,000 帧。进度同时显示目标样本数和源帧数。会话与 CSV 使用 `-sampled` 模式后缀和 `sampled` 完成状态，帧间快速动作可能漏采。

部分人体入镜时，保留仍有可信观测的点。人体形态检查按源画面宽高比计算投影长度；出框或坐标异常的点记为不可用。关节所需各点均达到置信阈值，且原始投影的两段均足够长时才计算角度。整帧无可信姿态时仍保留时间戳，角度和速度留空；短暂丢失后，模型会尝试从整幅画面重新寻找姿态。摄像头和离线视频都使用此规则。缺失不会被平滑或插值成有效测量。拍摄时建议使用稳定光源、固定机位，并让待测关节尽量无遮挡。

暂停时保持背压，恢复不重复写帧。取消、重置和换源后关闭资源并拒绝迟到写入。会话拒绝帧时解码任务终止，不把已丢失样本计为完成。

采集元数据记录预期/已处理帧数、状态、编码、旋转和时间偏移，随工具证据及 CSV 导出。合成素材来源由用户明确标记。

必要回归素材位于 tests/fixtures，含固定哈希和独立时间戳 oracle；这些素材不证明真实运动视频精度。当前验证见 [项目评估](project-assessment.md)。
