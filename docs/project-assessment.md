## 主要问题

### P1：真实模型不能稳定完成核心目标

命令：

```powershell
node scripts/evaluate-agent.mjs --model qwen2.5:7b-instruct --repeat 1 --case compare,multi_turn,quality --max-business-requests 12 --max-business-ms 120000 --output .qa/fresh-review-20261029/agent-evaluation.json
node scripts/evaluate-agent.mjs --model qwen2.5:7b-instruct --repeat 1 --case multi_turn --max-business-requests 12 --max-business-ms 90000 --output .qa/fresh-review-20261029/agent-multi-turn.json
```

第一条实际执行比较、质量两项，共 12 次业务请求，均未通过；预算用尽后未执行多轮，不能把未执行项算作失败样本。随后单独执行多轮用例。

- 比较约 39.8 秒后达到错误恢复上限：比较视图范围声明错误，之后计划步骤数组越界。没有交付要求的比较和视图。
- 质量查询约 23.3 秒后达到恢复上限：来源缺失、sessionId 参数冲突；后来虽成功查询质量，仍因额外定位参数冲突而没有完成交付。
- 多轮首轮反复生成父子字段重叠来源；修改轮继续出现同类错误，随后业务时间预算终止。

执行器正确拒绝了错误参数，但当前模型与协议组合的可用性不足。应先让固定的比较、质量、多轮目标在真实模型下稳定完成，再增加新功能。上述观察仅适用于本次模型、参数和输入，不能泛化为所有模型均失败。

### P2：姿态对比没有统一参数与坐标几何

`src/components/PoseCompare.vue:9` 接收 settings，但在约第 103 行硬编码 threshold=0.5/window=5；第 107 行调用 poseDistance 时也使用默认阈值。用户调整的主工作区置信阈值不会作用到对比距离。

`src/utils/poseMath.ts:216` 的 poseDistance 直接对各视频归一化 x/y 做平移、尺度归一化，没有接收各自来源比例。相同物理坐标在 1:1 与 2:1 画幅中的表示，本次最小复现得到距离 **0.2420369938646184**，而按来源比例还原后应为 0。因此横竖比例不同的视频可能产生几何偏差，现有平移/缩放测试不能覆盖它。

对比页还使用主线程同步双模型推理、约 10 Hz 定时采样与 0.12 秒漂移修正；没有逐帧对齐和序列时间配准证据。它适合描述性预览，暂不宜把距离解释为严格的动作序列相似度。

### P2：真实输入与设备性能缺少本次验证

本次没有使用真实摄像头或包含人体运动的长视频，也没有测试原生保存对话框、手机、休眠恢复和跨浏览器行为。Node 基准和合成色块只能验证代码链路与数据契约。

摄像头路径在 `PoseStage.vue` 主线程调用 detectForVideo；离线视频使用 Worker。两条路径的 UI 响应性需要分别实测，不能互相替代。

### P3：测试与交付维护仍有缺口

- 浏览器测试的协议版本仍写为 3.0.0，而当前实现为 3.1.0，本次已修正。此前可导致两个实际成功的流程被断言为失败。
- GitHub Actions 目前只运行格式、lint、单元测试和 build，没有浏览器回归步骤；远程 CI 本次未查询。
- App.vue 为 1,233 行，兼管输入源、会话、视图、导出和 Agent 端口，后续修改容易互相影响。
- Agent 参数、审计与成果默认展开较多，三轮流程的本次全页截图高 7,137 px。常用结论与技术细节需要更清晰的展开层次。
- ECharts 已按模块注册，但构建后的 charts chunk 仍约 595 kB（gzip 约 201 kB）；可以评估按页面加载图表。当前这是体积告警，不是构建失败。
- 仓库未提供 LICENSE 文件；正式对外分发前，项目授权选择尚需明确。

## 本次长会话基准

环境为 Windows、Node v24.22.1；输入是 18,000 帧合成姿态，不含模型推理。执行命令：

```powershell
node --expose-gc scripts/benchmark-session.mjs 18000 .qa/fresh-review-20261029/benchmark
```

| 指标 | 本次结果 |
| --- | ---: |
| 合成会话构建 | 853 ms |
| 全区间首次指标查询 | 52.46 ms |
| 缓存查询中位数（100 次） | 0.0224 ms |
| 质量首次查询 | 42.17 ms |
| 会话保留堆内存增量 | 约 175.6 MiB |
| CSV 行数 / 字节 | 18,000 / 104,483,245 |
| CSV 文件写入 | 4.51 s |
| 再次仅哈希导出 | 3.59 s，字节数与 SHA-256 一致 |
| 首次导出采样 RSS 峰值 | 约 508.3 MiB |

会话本身仍全部驻留内存。分块写入减少导出过程的临时缓冲，但 Blob 回退仍保留整份文件。缓存命中很快，不能据此忽略第一次查询和内存成本。单次合成基准不构成浏览器性能或持续帧率保证。
